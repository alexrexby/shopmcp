# Конфигурация: store.toml

[English](../en/configuration.md) · **Русский**

Магазин описывается одним TOML-файлом. Он загружается в три шага: разбор TOML, подстановка `${ENV}`, проверка по моделям из `src/shopmcp/config.py`. Во всех секциях, кроме `[adapter]`, неизвестные ключи отклоняются, поэтому опечатка роняет старт, а не молча игнорируется. Рабочий пример — [`stores/demo/store.toml`](../../stores/demo/store.toml); шаблон для генерации — `src/shopmcp/templates/store.toml.tmpl`.

Содержание: [Переменные окружения](#переменные-окружения) · [Верхний уровень](#верхний-уровень) · [adapter](#adapter) · [cart](#cart) · [limits](#limits) · [server](#server) · [auth](#auth) · [tools](#tools) · [texts](#texts) · [conformance](#conformance) · [Ошибки](#ошибки)

## Переменные окружения

Секреты в файл не пишутся. Укажите `${VAR}` внутри любого строкового значения (в том числе во вложенных таблицах и списках) и задайте `VAR` в окружении процесса. Если переменная не задана, старт падает с сообщением, где назван путь в конфиге, например `error: store.toml.adapter.feed: environment variable FEED_TOKEN is not set`; пустой строкой она не подменяется.

```toml
[adapter]
kind = "yml"
feed = "https://feeds.example/export.xml?token=${FEED_TOKEN}"
```

Помимо конфига процесс читает одну переменную:

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `SHOPMCP_DATA_DIR` | Каталог поискового индекса (`<id магазина>.sqlite`); у `serve` и `index` должен совпадать | `data` (`/data` в Docker-образе) |

## Верхний уровень

| Поле | Назначение | По умолчанию |
|---|---|---|
| `id` | Идентификатор магазина, `^[a-z][a-z0-9-]{1,31}$`. Даёт имя файлу индекса и каталогу `stores/<id>/` | обязательно |
| `prefix` | Префикс имён инструментов, `^[a-z][a-z0-9]{1,15}$`: инструменты называются `<prefix>_products_search` и т. д. | обязательно |
| `brand` | Название магазина для модели; становится `serverInfo.name` | обязательно |
| `site` | URL сайта магазина | обязательно |
| `locale` | `ru` или `en`: язык всех текстов для модели (описания инструментов и параметров, instructions, ошибки) | `ru` |
| `instructions` | Что продаёт магазин, цены, регионы. Добавляется к instructions сервера после сгенерированного вступления | пусто |
| `phone`, `delivery`, `payment` | Свободный текст, отдаётся инструментом `store_info` | не задано |
| `regions` | Список регионов работы, отдаётся в `store_info` | `[]` |

Instructions сервера собираются из: вступления (`instructions.intro`), вашего `instructions`, правила про корзину (если инструмент корзины есть) и правила про вход (если есть персональные инструменты). `locale` определяет язык сгенерированных частей; ваш текст используется как написан.

## adapter

`kind` выбирает адаптер; остальные ключи таблицы принадлежат адаптеру и проверяются им. Зарегистрированные виды: `yml` и `feed` (один адаптер, см. ниже), `woocommerce`, `bitrix`, `insales`, `http_json` (последние три — заглушки, см. [adapters.md](adapters.md)). Неизвестный `kind` даёт ошибку со списком известных.

Ключи `yml` и `feed` (`feed` — тот же адаптер под именем, которое scaffold пишет для пресетов движков):

| Ключ | Назначение | По умолчанию |
|---|---|---|
| `feed` | `https://`-URL или путь; относительный путь отсчитывается от каталога `store.toml`, а не от текущего каталога | обязательно |
| `format` | `auto`, `yml` или `gmc`. `auto` различает форматы по корневому элементу: `yml_catalog` — YML, `rss` и Atom `feed` — Google Merchant. Явное значение, не совпадающее с корнем, роняет чтение | `auto` |
| `refresh_minutes` | Как часто индекс перестраивается в фоне; `0` отключает обновление | `60` |
| `max_feed_mb` | Предел размера фида в мегабайтах; фид больше отклоняется | `200` |
| `stale_minutes` | Индекс старше этого считается устаревшим: `/healthz` отвечает `503`. Должен быть больше `refresh_minutes`; при `refresh_minutes = 0` не действует | `3 × refresh_minutes` |
| `cart_ref` | Таблица `[adapter.cart_ref]`, см. ниже | не задано |

Любой другой ключ в `[adapter]` для этих видов — ошибка.

Ключи `woocommerce`:

| Ключ | Назначение | По умолчанию |
|---|---|---|
| `site` | `https://`-URL сайта на WordPress, без query: `https://shop.example` или `https://shop.example/shop` | обязательно |
| `refresh_minutes`, `stale_minutes` | Как у `yml` | `60`, `3 × refresh_minutes` |
| `max_pages` | Сколько страниц (по 100 товаров) читается из одного листинга; магазин больше отклоняется с названием этого ключа | `200` |
| `max_minutes` | Бюджет времени одного полного чтения, в минутах | `30` |
| `max_feed_mb` | Предел байтов всего чтения, все страницы вместе | `200` |

У адаптера `woocommerce` нет ни `cart_ref`, ни `feed`. Как он читает магазин: [adapters.md](adapters.md#адаптер-woocommerce).

### adapter.cart_ref

Ссылке корзины нужен ключ, который знает корзина магазина, а он не всегда совпадает с `id` фида. `[adapter.cart_ref]` описывает, как получить его из id фида. Без таблицы действует умолчание: предложение с группой (`group_id` в YML, `g:item_group_id` в GMC) — вариант этой группы (`{product_id}` — группа, `{variant_id}` и `{id}` — id предложения); предложение без группы — товар (`{id}` — его id).

| Ключ | Назначение |
|---|---|
| `pattern` | Регулярное выражение, которому должен целиком соответствовать id фида (full match), с именованной группой `product_id` и, по желанию, `variant_id`; других именованных групп нет. Id, не подошедший под выражение, обрабатывается по умолчанию |
| `options` | Таблица `имя опции магазина = "имя param фида"`: значение `param` предложения (YML) или атрибута (GMC: `color`, `size`, `material`, `pattern`, `gender`, `age_group`) уходит в корзину как эта опция. До 20 записей |

```toml
[adapter.cart_ref]
pattern = "^(?P<product_id>[0-9]+)-(?P<variant_id>[0-9]+)$"   # id фида "12-34"
options = { Size = "size" }
```

Неизвестный ключ, не компилирующееся выражение или неверные имена групп роняют старт с путём ключа.

## cart

Как корзина передаётся на сайт магазина. Инструмент — `<prefix>_cart_link_create`; он сначала сверяет все id с каталогом, поэтому неизвестный id даёт ошибку со списком таких id. `scaffold --engine` пишет готовый `[cart]` для каждого движка, см. [engines.md](engines.md).

`strategy` выбирает стратегию и определяет, какие ещё ключи допустимы; ключ другой стратегии — ошибка. Без `[cart]` или без `strategy` это `link_list`.

| Стратегия | Кто наполняет корзину | Ключи |
|---|---|---|
| `link_list` | покупатель, по ссылкам на карточки | `line_template` |
| `url_template` | магазин, по одной GET-ссылке | `url_template`, `item_template`, `item_separator` |
| `json_fragment` | скрипт магазина, из фрагмента URL (Ecwid) | `url_template`, `payload_encoding` |
| `form_post` | наша страница-трамплин `/cart/h/<токен>` на этом сервере, POST-ом в магазин (бета) | `action`, `mode`, `fields`, `finish_url`, `secret`, `ttl_minutes` |
| `receiver` | наш модуль на сайте магазина, по подписанной ссылке | `url_template`, `secret`, `key_id`, `ttl_minutes` |
| `share_link` | API магазина, общая корзина | нет |

| Ключ | Стратегия | Назначение | По умолчанию |
|---|---|---|---|
| `line_template` | `link_list` | Ссылка-добавление на каждую позицию (отдаётся как `add_url`); должна содержать `{id}` или `{product_id}`. Без неё возвращаются только ссылки на карточки | не задано |
| `url_template` | `url_template`, `json_fragment`, `receiver` | URL корзины; должен содержать соответственно `{items}`, `{payload}` или `{token}` | обязательно |
| `item_template` | `url_template` | Одна позиция корзины; должна содержать `{id}` или `{product_id}` | обязательно |
| `item_separator` | `url_template` | Строка между позициями | `&` |
| `payload_encoding` | `json_fragment` | `uri` (JSON с процентным кодированием) или `base64` (Ecwid на Wix) | `uri` |
| `action` | `form_post` | URL, на который отправляется форма; на сайте магазина, как и любой URL секции | обязательно |
| `mode` | `form_post` | `single`: одна форма со всеми позициями; `chain`: форма на каждую позицию, магазин возвращает браузер обратно | обязательно |
| `fields` | `form_post` | Список пар `[имя, значение]`, 1-10, обе части — шаблоны; поле, давшее пустое значение, не отправляется. Хотя бы одно должно содержать `{id}` или `{product_id}` | обязательно |
| `finish_url` | `form_post` | Где кончается цепочка: страница корзины. Обязателен для `chain` | не задано |
| `secret` | `form_post`, `receiver` | Ключ подписи: ровно одна ссылка `${ENV}` (литерал в файле отклоняется), не короче 32 байт после подстановки | обязательно |
| `ttl_minutes` | `form_post`, `receiver` | Срок жизни подписанной ссылки, 5-10080 | `1440` |
| `key_id` | `receiver` | Идентификатор ключа в токене (`kid`), для ротации: `^[A-Za-z0-9._-]{1,32}$` | `1` |

Плейсхолдеры шаблонов. Подставляются за один проход (подставленное значение заново плейсхолдером не читается), каждое значение целиком кодируется процентным кодированием, поэтому безопасно в пути, query и фрагменте:

| Плейсхолдер | Значение |
|---|---|
| `{id}` | самый конкретный id корзины: id варианта, если вариант есть, иначе id товара |
| `{product_id}` | id товара из ключа корзины |
| `{variant_id}` | id варианта; пусто, если варианта нет |
| `{qty}` | количество |
| `{url}` | URL карточки товара; не кодируется там, где с него начинается шаблон (`{url}?action=...`), в значении query кодируется |
| `{items}` | `url_template`: позиции, каждая по `item_template`, через `item_separator` |
| `{payload}` | `json_fragment`: корзина JSON-ом в выбранной кодировке |
| `{token}` | `receiver`: подписанный токен |

В `line_template` query-параметр, плейсхолдер которого дал пустое значение, опускается (`id_product_attribute=` у товара без комбинаций). В `item_template` он остаётся: параллельные массивы (`product[]`, `variant[]`) связывают позиции по номеру.

Слоты времени scaffold. В пресете (`src/shopmcp/engines.py`) URL содержат `{origin}` (схема, хост и порт из `--site`; магазин на http остаётся на `http`), `{base}` (`{origin}` плюс путь из `--site`, для движка в подкаталоге), `{host}` (хост и порт), `{feed}`, `{cart_path}`. `shopmcp scaffold` подставляет их при записи `store.toml`; в готовом файле их нет, и плейсхолдерами времени работы они не являются.

Стратегии:

- `link_list` работает в любом магазине: ссылки на карточки товаров с количествами. С `line_template`, например `https://shop.example/cart/?add-to-cart={id}&quantity={qty}`, у каждой позиции есть ещё и ссылка, добавляющая именно её.
- `url_template` собирает один URL, например `https://shop.example/cart/add?id[]=1&qty[]=2&id[]=5&qty[]=1`. Если URL получился бы длиннее 2000 символов, ответ деградирует до `link_list` с пояснением.
- `json_fragment`: `url_template` вида `https://shop.example/#!/~/cart/create={payload}`; корзина — `{"products":[{"id":…,"quantity":…,"options":{…}}]}`. Та же деградация при 2000 символах.
- `form_post` — **бета**. Ссылка ведёт на страницу-трамплин этого сервера, `<origin из server.public_url>/cart/h/<токен>`; страница отправляет позиции POST-ом на `action` из браузера покупателя. `mode = "single"` шлёт одну форму, `"chain"` — форму на позицию и требует `finish_url`. Исход зависит от того, где размещён сервер относительно магазина: размещайте его на поддомене магазина, а как `shopmcp check` (C11) оценивает пару, читайте в [engines.md](engines.md#form_post-бета) и [conformance.md](conformance.md#как-c11-оценивает-form_post). В `fields` допустимы только `{id}`, `{product_id}`, `{variant_id}`, `{qty}`; любой другой плейсхолдер останавливает старт. Имя поля с `[` или `]` в id (`variant_ids[{id}]` и id `a[b]`) изменило бы структуру для Rails и PHP, поэтому такая корзина деградирует до `link_list` с пояснением.
- `receiver` строит ссылку на модуль на сайте магазина; формат токена и контракт модуля — в [cart-receiver.md](cart-receiver.md). Та же деградация при 2000 символах; в ответе есть `expires_at`.
- `share_link` просит адаптер создать общую корзину на стороне магазина. Адаптер обязан объявить capability `share_link`, иначе старт падает. Инструмент при этом помечается как не только читающий (он создаёт объект в магазине).

Каждый URL секции (`url_template`, `line_template`, `action`, `finish_url`) обязан указывать на хост `site` или его поддомен, иначе старт падает: ссылка корзины на чужой хост сделала бы магазин открытым редиректом. `line_template`, начинающийся с `{url}`, исключение: он стартует со страницы товара, которой владеет фид.

## limits

| Поле | Назначение | Диапазон | По умолчанию |
|---|---|---|---|
| `max_page_size` | Наибольший `limit`, который принимает постраничный инструмент | 1-100 | `20` |
| `max_cart_lines` | Позиций в одной корзине; становится `maxItems` схемы корзины | 1-200 | `30` |
| `max_quantity` | Количество в одной позиции корзины | 1-10000 | `99` |
| `max_response_bytes` | Бюджет размера ответа инструмента. Постраничный ответ сверх бюджета теряет элементы с конца и получает `meta.truncated = true` | >= 1024 | `24000` |
| `rate_per_minute` | Запросов в минуту с одного IP (token bucket); сверх лимита — `429` с `Retry-After`. `/healthz` не считается | >= 1 | `60` |

Лимиты записываются в схемы и описания инструментов, поэтому модель видит те же числа, что применяет сервер (проверка C5 это контролирует).

## server

| Поле | Назначение | По умолчанию |
|---|---|---|
| `path` | Путь MCP-эндпоинта, `^/[a-z0-9/_-]*$` | `/mcp` |
| `host` | Адрес привязки | `0.0.0.0` |
| `port` | Порт, 1-65535 | `8000` |
| `public_url` | Публичный URL эндпоинта. Это защищаемый ресурс в RFC 9728 и обязательная аудитория (`aud`) токена | обязательно |
| `allowed_hosts` | Допустимые значения заголовка `Host` (защита от DNS rebinding); `*` вместо порта — любой порт | `["localhost:*", "127.0.0.1:*"]` |
| `allowed_origins` | Допустимые значения заголовка `Origin`; `*` как шаблон порта (`http://localhost:*`). Непустой список также включает CORS на MCP-пути для этих origin — для браузерных клиентов | `[]` |
| `trusted_proxies` | Адреса или сети, чьему `X-Forwarded-For` верить при подсчёте лимита запросов | `[]` |

За реверс-прокси: добавьте публичный хост (например `"mcp.shop.example"`) в `allowed_hosts`, укажите в `public_url` публичный адрес и внесите прокси в `trusted_proxies`. Без `trusted_proxies` все запросы выглядят пришедшими от прокси и делят одну корзину лимита. `X-Forwarded-For` читается справа налево до первого адреса, которому не доверяют. IPv6-клиенты считаются по подсети /64.

CORS: при пустом `allowed_origins` (по умолчанию) браузер с другого origin не может вызвать эндпоинт; серверным клиентам CORS не нужен. Origin из списка получает `204` на preflight и `Access-Control-Allow-Origin` со своим значением в каждом ответе MCP-пути, включая `401`, `403` и `429`. Разрешённые заголовки запроса: `content-type`, `authorization`, `last-event-id` и `mcp-*`. `*` не отдаётся никогда, учётные данные (cookies) не разрешаются: токен передаётся в `Authorization`.

Сервер отвечает только на `POST` по `path`; `GET` получает `405`, потоки открытыми не держатся.

## auth

| Поле | Назначение | По умолчанию |
|---|---|---|
| `enabled` | Включить проверку токенов | `false` |
| `issuer` | Ожидаемый `iss` токена и сервер авторизации, который объявляется в метаданных. Голый хост совпадает и со слэшем на конце, и без него, см. [auth.md](auth.md) | пусто |
| `jwks_uri` | URL набора ключей сервера авторизации | пусто |
| `tool_scopes` | Таблица `суффикс инструмента = ["scope", ...]`: какие scope нужны для вызова; переопределяет умолчание инструмента. Список не может быть пустым | `{}` |

`enabled = true` требует и `issuer`, и `jwks_uri`. Ключ в `tool_scopes`, не являющийся суффиксом известного инструмента, роняет старт. Подробности, ответы на ошибки и модель доверия: [auth.md](auth.md).

```toml
[auth]
enabled = true
issuer = "https://auth.shop.example"
jwks_uri = "https://auth.shop.example/.well-known/jwks.json"
[auth.tool_scopes]
orders_history = ["orders.read"]
```

## texts

Каждый текст, который читает модель, существует во фреймворке на двух языках; `locale` выбирает один. `[texts]` заменяет любой из них по ключу, на языке магазина:

```toml
locale = "ru"

[texts]
"tool.products_search.description" = "Поиск по каталогу Демо-маркета."
"tool.products_search.param.q" = "Слова для поиска, например название товара"
"instructions.intro" = "Ты работаешь с каталогом магазина {brand} ({site})."
```

Виды ключей:

| Ключ | Текст |
|---|---|
| `tool.<суффикс>.title` | Заголовок инструмента |
| `tool.<суффикс>.description` | Описание инструмента |
| `tool.<суффикс>.param.<имя>` | Описание одного параметра инструмента |
| `instructions.intro`, `instructions.cart`, `instructions.sign_in` | Части instructions сервера |
| `cart.note.url_too_long` | Пояснение, когда корзина `url_template` деградирует до списка ссылок |
| `error.<код>` | Сообщение по умолчанию для кода ошибки: `not_found`, `invalid_input`, `upstream_unavailable`, `not_supported`, `unauthorized`, `internal_error` |

Правила:

- Ключ соответствует `^[a-z][a-z0-9_]*(\.[a-z][a-z0-9_]*)+$`. Ключ, который не использует ни один текст, роняет старт: опечатка не может молча ничего не сделать.
- Ключи отключённого инструмента остаются допустимыми: проверка идёт по полному набору инструментов фреймворка.
- Подстановки в instructions выполняются простой заменой: `{brand}`, `{site}` (вступление), `{cart_tool}` (корзина), `{personal_tools}` (вход). Переопределение вправе опустить их или повторить.
- Имена инструментов, схемы и имена полей текстами не являются и не переопределяются.
- Точные имена параметров и встроенные тексты — в `src/shopmcp/tools/*.py` и `src/shopmcp/server/instructions.py`.

## Ошибки

Неверный конфиг останавливает команду с кодом `1` и сообщением, где назван путь к полю. Входные значения в сообщение не попадают: после подстановки `${ENV}` они могут быть секретами. Реальные примеры:

```text
error: bad.toml: server.public_url: Field required
error: bad.toml.adapter.feed: environment variable NOPE_FEED is not set
error: bad.toml: auth: Value error, auth.enabled requires auth.issuer and auth.jwks_uri
error: texts: unknown keys ['tool.nope.description']
```
